# agentcore-pingone-demo-LAB

Demo-tier standalone app (Tier: Demo, catalog D99 placeholder): an AI agent on AWS Bedrock AgentCore Runtime whose identity comes from PingOne, MOCK only. Tabs: (1) M2M gate (`oauth2_flow=M2M` client_credentials, verified shape; `client_id` + object `act.sub` against a downstream required-claims rule; five scenarios incl. the act-as-text-"{}" trap), (2) USER_FEDERATION 3LO (pi.flow human sign-in, code to callback, exchange; seven scenarios each breaking one of the four measured shapes: exact callback match, sessionUri pre-registration, POST token-endpoint auth, GetResourceOauth2Token IAM), (3) On-behalf-of (RFC 8693 mock engine, 13 scenarios, Ping release claim UNVERIFIED), (4) Diagram (diagram-studio/1 data, movable boxes), (5) Talk track + presenter mode. Every row is tagged measured / inferred / UNVERIFIED / lab-invented.

- Run: `npm start` (http://127.0.0.1:7601). Test: `npm test` (server is `node --test test/*.test.js`, a glob; web is vitest; scripts). Preflight: `npm run doctor`. Reset: `npm run reset` or `POST /api/reset`. Docker: `HOST_PORT=7601 docker compose up --build -d` (127.0.0.1 only). Node 26 only.
- Modes: rule 19. `GET /api/info` returns `{source, realAvailable, realReason}`; `POST /api/mode` with exactly `{source}` switches at runtime (409 when Real is unconfigured). Real = a live AgentCore Runtime + PingOne tenant, owner-built and owner-run: this build ships the Mock engine only; `realConfigured` in `server/src/real.js` gates the offer (needs `APD_REAL_ENGINE=1` + the PingOne worker settings). Do not build a Real engine without the owner.
- Settings: the one shared file `~/Development/.env` (or `STANDALONE_ENV`), parsed with `util.parseEnv` in `server/src/env.js`; read-only, and no value is ever printed or returned. Never a bare `MODE`, never a per-app `.env` loader.
- Core: `server/src/claims.js` (M2M claim matching, bounded), `server/src/threeLo.js` + `threeLoData.js` (the 3LO step machine), `server/src/obo.js` (the exchange engine). Story data uses `{{castBrand}}`-style tokens filled by `cast.js` (3 vertical packs); a test fails on an undefined token. Diagrams: `server/diagrams/*.json` (diagram-studio/1, loaded by name by `diagramData.js`).
- API: `GET /api/scenarios`, `POST /api/evaluate`, `GET /api/three-lo`, `POST /api/three-lo/evaluate`, `GET/POST /api/obo...`, `GET /api/diagram`, `GET /api/runs`, `POST /api/reset`, `GET /api/info`, `POST /api/mode`, `GET /api/health` (demo-health/1). Workspace id in `X-Workspace`.
- Typed text, ALL endpoints: the custom token is masked on the way out (`maskTypedDeep`), every answer goes through `maskDeep`; `masking.test.js` is the sweep. A fixed lab text must not read as an assignment (`token:` followed by a word): reword it. A fixed text mentioning `Authorization` must not use the `Authorization: <word>` header shape (the masker blanks it): reword.
- Generated files: change the engine or the data, then `npm run talk-track` and `npm run content-pack`; tests fail on drift. Web banner text is pinned to `releaseClaims.js`/`claimsData.js` by repo tests.
- Web: `web/src/App.jsx` (tabs, ModeToggle, presenter, Reset, X-Workspace via `workspace.js`). UI: `web/src/styles/standalone-ui.css` vendored byte-for-byte from AI-DEMO-Standalone (never edit it); `app.css` is layout only, tokens only. Diagram: `PatternDiagram` + `hooks/useDiagramStepper`.
- Rules that bite: loopback bind only; same-origin writes; zero outbound network (netguard incl. UDP connect, with a self-test); only `.example`/`.invalid` hosts; ports 7601-7649; tokens are mock-issued and shown raw; no k8s or SE build (deferred by the owner); no identifiers from other projects.
- Claims status: the M2M call shape and the four 3LO shapes are measured on the owner's verified build (2026-08-12); the step order, codes, code lifetime and user store are the lab's own model. On-behalf-of is a Ping release claim, UNVERIFIED on our tenant.
- Run check-css and conformance by hand (they are not in this repo's CI).
